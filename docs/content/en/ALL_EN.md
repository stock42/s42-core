# S42-Core Master Documentation (ALL_EN)

Last reviewed: 2026-07-27
Package baseline: `s42-core@3.0.10`
Runtime requirement: Bun `>=1.3.0`

This document is the primary technical overview of the repository. It describes
the behavior implemented by `src/`, not an aspirational API.

## 1. Framework Scope

S42-Core is a Bun-first TypeScript framework for:

- HTTP services based on `Bun.serve` and Web `Request`/`Response`.
- Convention-based, module-oriented service composition.
- Distributed domain events through Redis or SQS adapters.
- MongoDB, Redis/Valkey, PostgreSQL, MySQL, and SQLite access.
- Worker clustering, SSE, introspection, logging, and small runtime utilities.

The package is ESM and ships its TypeScript source. The supported package
boundary is the root export map in `package.json`, backed by `src/index.ts`.

## 3. Installation and Minimal Bootstrap

```bash
bun add s42-core
```

```ts
import { Modules, RouteControllers, Server } from 's42-core'

const modules = new Modules('./modules')
await modules.load()

const server = new Server()
await server.start({
	port: 5678,
	RouteControllers: new RouteControllers(modules.getControllers()),
	hooks: modules.getHooks(),
})

console.info(server.getURL())
```

`Server.start()` resolves after `Bun.serve` has been created (and, when
requested, after the cluster start signal). S42-Core currently does not expose a
public `Server.stop()` wrapper.

The repository includes this local module demo entrypoint:

```bash
bun run modules/server.ts
```

In the current checkout, that demo stops while importing
`modules/operators/controllers/operatorList.ts`: the controller references the
missing `../events/emit` fixture. The minimal package bootstrap above is not
affected.

## 4. Runtime Mental Model

Typical startup:

1. Create database, Redis, and other shared clients.
2. Optionally register them in `Dependencies`.
3. Create `EventsDomain` if modules use events.
4. Create `Modules(path, eventsDomain?)` and call `load()`.
5. Create `RouteControllers` from `modules.getControllers()`.
6. Start `Server`.

Typical HTTP request:

1. Bun attempts the native route map generated by `getRoutes()`.
2. The fallback callback handles wildcard or otherwise unsupported patterns.
3. `RouteControllers` normalizes the request.
4. Matching global `before` hooks run.
5. Controller-specific `mws` before handlers run.
6. The controller handler returns a `Response`.
7. Controller-specific `mws` after handlers run.
8. Matching global `after` hooks run.
9. The original controller response is returned.

Typical domain event:

1. The name is normalized to uppercase and `$` becomes `.`.
2. The event must have a registered emitter.
3. Listener instances are selected from the distributed registry.
4. The adapter publishes to instance-specific channels.

## 5. Module System

`Modules` scans `**/__module__.ts` below the configured path using `Bun.Glob`.
Each default export is parsed with the public `Module` Zod schema.

### 5.1 Manifest

```ts
export default {
	name: 'operators',
	version: '1.0.0',
	type: 'full',
	enabled: true,
	dependencies: [{ module: 'auth', version: 1 }],
	initialize: async () => {
		console.info('operators ready')
	},
}
```

Contract:

```ts
{
  name: string
  version: string
  type?: 'mws' | 'share' | 'full' // default: 'full'
  enabled?: boolean               // default: true
  initialize?: () => unknown | Promise<unknown>
  dependencies?: Array<Record<string, unknown>>
}
```

Current semantics:

- `enabled: false` skips the entire module.
- `initialize` runs after the module's type-specific load step and is awaited.
- `dependencies` is validated metadata only. The loader does not resolve,
  order, or enforce dependency versions.
- Order inside each module type follows discovery order; do not rely on
  alphabetical ordering.

### 5.2 Module types and load order

The loader processes all enabled modules in this order:

1. `mws`
2. `share`
3. `full`

#### `mws`

Required layout:

```text
auth/
  __module__.ts
  mws/
    index.ts
```

`mws/index.ts` must export:

- a default initialization function;
- `beforeRequest`;
- `afterRequest`, or the compatibility alias `exportRequest`.

Direct hook form:

```ts
export default async () => {
	// one-time initialization
}

export async function beforeRequest(req: Request, res: Response, next: Function) {
	if (!req.headers.get('authorization')) {
		throw new Error('Token required')
	}
	next(req, res)
}

export function afterRequest(req: Request, res: Response, next: Function) {
	next(req, res)
}
```

Compatibility behavior also accepts a hook that returns another hook function.
The loader auto-advances when a middleware does not call `next()`.

#### `share`

A `share` module registers metadata only. It does not automatically import
services, types, models, controllers, events, or middleware. Code inside the
module remains available through normal project imports.

If a `share` module contains `controllers/`, `events/`, or `mws/`, those
directories are ignored and a warning is logged when detected.

#### `full`

A `full` module:

- imports every `*.ts` file below `controllers/`;
- optionally imports event files below `events/`;
- runs `initialize` after controllers and events are processed.

Each controller file must default-export controller metadata:

```ts
import type { ControllerType } from 's42-core'

export default {
	name: 'operatorList',
	version: '1.0.0',
	method: 'GET',
	path: '/operators/list',
	requireBefore: ['auth'],
	handler: async (req, res, { events }) => {
		events.emit('Operator$List$Completed', { ok: true })
		return res.json({ ok: true, docs: [] })
	},
	handleError: async (_req, res, error) => {
		return res.status(500).json({ ok: false, error: String(error) })
	},
} satisfies ControllerType
```

Controller metadata supports:

- `method`: `GET`, `POST`, `PUT`, `DELETE`, or `PATCH`;
- `path`;
- `handler(req, res, { events })`;
- optional `handleError(req, res, error)`;
- `requireBefore` / `beforeRequest`;
- `requireAfter` / `afterRequest`;
- optional `enabled` metadata.

Important current behavior:

- The loader does not call `Controllers.parse()` for imported controller files.
- `enabled` on controller metadata is not used to filter a controller. Only the
  module-level `enabled` flag controls loading.
- Every TypeScript file under `controllers/` is imported and expected to have a
  compatible default export.

### 5.3 Controller-level middleware

Middleware modules are opt-in per controller:

```ts
requireBefore: ['auth']
requireAfter: ['audit']
```

Aliases:

```ts
beforeRequest: ['auth']
afterRequest: ['audit']
```

Special reference:

```ts
requireBefore: ['mws'] // every loaded middleware module
```

References are de-duplicated. An unknown middleware name logs a warning and is
skipped.

### 5.4 Events inside module controllers

The handler context exposes:

```ts
{
  events: {
    emit(eventName: string, payload?: unknown): void
  }
}
```

The module name is prefixed before `EventsDomain` normalizes the event:

```text
module "operators" + "Operator$List$Completed"
=> OPERATORS.OPERATOR.LIST.COMPLETED
```

If no `EventsDomain` was passed to `Modules`, controller execution continues but
this facade has no configured event bus.

### 5.5 Event file conventions

With an `EventsDomain` configured:

- Non-function named exports from `events/emit.ts` register emitters.
- Function exports from other event files register listeners.
- `EVENTS` can map handlers to explicit event names and `multiple` behavior.
- A default listener is registered only when `EVENTS` supplies its event name.
- Named handler exports fall back to their export name when no explicit mapping
  is present.

Explicit mapping is the clearest form:

```ts
import type { EventType } from 's42-core'

export const EVENTS = {
	onApproved: {
		eventName: 'ORDERS.ORDER.APPROVED',
		multiple: false,
	},
}

export async function onApproved(event: EventType) {
	console.info(event.payload)
}
```

### 5.6 `Modules` API and current compatibility getters

Instance methods:

- `load()`
- `setEventsDomain(eventsDomain)`
- `getControllers()`
- `getHooks()`
- `getSharedModules()`
- `getLoadedModules()`
- `getServices()`
- `getModels()`
- `getTypes()`

`getModulesStats()` is a standalone root export, not an instance method.

Current compatibility details:

- `mws` middleware is attached directly to opted-in controllers, so
  `getHooks()` currently returns the internal global-hook array, which the
  loader does not populate.
- Models, services, and types are not auto-discovered; their getters currently
  return empty collections or `undefined`.

## 6. HTTP Layer

### 6.1 `Server`

```ts
await server.start({
	port: 5678,
	clustering: false,
	idleTimeout: 300,
	maxRequestBodySize: 1_000_000,
	hooks: [],
	RouteControllers: router,
	development: false,
	awaitForCluster: false,
	error: () => new Response('Internal Server Error', { status: 500 }),
})
```

Options and defaults:

| Option               |                Default | Meaning                                                  |
| -------------------- | ---------------------: | -------------------------------------------------------- |
| `port`               |         `0` at runtime | Bun listener port; TypeScript contract requires a number |
| `clustering`         |                `false` | Passed to Bun as `reusePort`                             |
| `idleTimeout`        |                  `300` | Bun idle timeout                                         |
| `maxRequestBodySize` |            `1_000_000` | Maximum request body bytes                               |
| `hooks`              |                   `[]` | Global route hooks                                       |
| `RouteControllers`   |                   none | Router and route-map source                              |
| `development`        |                `false` | Bun development mode                                     |
| `awaitForCluster`    |                `false` | Wait for cluster `start` IPC command                     |
| `error`              | built-in HTML response | Bun error handler override                               |

Without `RouteControllers`, the server returns plain-text `404` responses.

Security note: the built-in error handler includes the error message and stack
in an HTML response. Production services should pass a sanitizing `error`
handler and log internal details through a protected sink.

Helpers:

- `getPort()`
- `getURL()`
- `isStartedFromCluster()`
- `getClusterName()`
- `sendMessageToCluster(message)`
- `sendMessageToWorkers(message)`
- `onMessageFromWorkers(callback)`

### 6.2 `RouteControllers`

```ts
const router = new RouteControllers(controllers)
```

Public methods:

- `getRoutes(hooks)`: produces Bun native routes for supported methods and paths.
- `getCallback(hooks)`: produces the fallback `fetch` callback.

Native route-map eligibility:

- methods: `GET`, `POST`, `PUT`, `DELETE`, `PATCH`, `OPTIONS`, `HEAD`;
- paths without `*`.

Method `*`, non-standard `UPDATE`, and wildcard paths use the fallback matcher.
Static paths, `:param` segments, and terminal wildcard matching are supported by
the fallback implementation.

#### Normalized controller request

Handlers receive this framework object, not the raw Web `Request`:

```ts
{
	headers: Headers
	realIp: string
	query: Record<string, string>
	body: Record<string, unknown>
	url: string
	method: string
	params: Record<string, string>
	formData: () => FormData
}
```

Parsing behavior:

- JSON is parsed for non-GET, non-form requests; invalid JSON becomes `{}`.
- `multipart/form-data` and URL-encoded bodies are parsed once.
- Query values are decoded, values containing `=` are preserved, and the last
  repeated key wins.
- `realIp` trusts `x-forwarded-for`, then `cf-connecting-ip`, then falls back to
  `::1`; only trust these headers behind a controlled proxy.
- The normalized object does not currently expose the raw request or its abort
  signal.

#### Global hooks

Hooks match method and path using exact, `:param`, or `*` segments.

Execution:

1. matched `before` hooks;
2. controller;
3. matched `after` hooks.

Current semantics:

- The pipeline auto-advances even when a hook does not call `next()`.
- Returning a `Response` from a hook does not replace or short-circuit the route
  response.
- A thrown `before` error returns JSON. Messages containing token/auth/
  unauthorized/forbidden are mapped to `401`; other errors map to `500`.
- A thrown `after` error is logged and the controller response is retained.
- After hooks cannot currently replace or mutate the already-built response.

#### Default response headers

Dispatched routes receive fixed no-cache, CORS, and CSP headers. Current CORS
behavior includes:

```text
Access-Control-Allow-Origin: *
Access-Control-Allow-Credentials: true
```

This is permissive and the wildcard/credentials combination is not accepted by
browsers for credentialed CORS. There is no public CORS configuration option
yet. Production deployments should enforce an explicit origin policy at a
trusted reverse proxy or an approved routing layer.

`OPTIONS` returns `204` only after the request reaches `dispatchRoute`; an
unregistered `OPTIONS` method can still miss route matching and return `404`.

### 6.3 `Controller`

```ts
const endpoint = new Controller('GET', '/health', async (_req, res) => {
	return res.json({ ok: true })
})
```

Methods:

- `setPath`, `getPath`, `getMethods`
- `get`, `post`, `put`, `patch`, `delete`, `options`, `update`
- `use`
- `getCallback`

`use(callback)` prepends the callback. The last `use()` call runs first. A
returned `Response` stops the controller middleware chain; other return values
advance it. If the chain ends without a response, S42-Core returns plain text
`End without response`.

The non-standard `UPDATE` method is retained for compatibility but is excluded
from Bun's native route map.

Every constructed `Controller` is tracked in the process-wide controller
statistics registry. `getControllersStats()` de-duplicates endpoint
method/path pairs and sorts them by path and method.

### 6.4 `Res`

`Res` builds Web `Response` instances:

- `status(code): this`
- `setHeader(key, value): void`
- `json(object): Response`
- `send(string): Response`
- `html(string): Response`
- `text(string): Response`
- `redirect(url): Response`

```ts
return res.status(201).json({ ok: true })
```

`json`, `html`, and `text` set their content type. `send` does not add one.
`redirect` always sets status `302` and the `Location` header.

## 7. EventsDomain

`EventsDomain` is a process singleton with a distributed listener/emitter
registry.

```ts
import { EventsDomain, RedisClient } from 's42-core'

const redis = RedisClient.getInstance('redis://127.0.0.1:6379')
await redis.connect()

const events = EventsDomain.getInstance(redis)
```

The first call to `getInstance(redis?, uuid?, clusterId?)` creates the singleton.
Later arguments do not reconfigure it. Cluster ID resolution is:

1. explicit `clusterId`;
2. `S42_CLUSTER_ID`;
3. `CLUSTER_NAME`;
4. `default`.

### 7.1 Event names

Standard event names:

- have at least three non-empty dot-separated segments;
- use only `[A-Z0-9_-]` per segment after normalization;
- are uppercased;
- convert `$` to `.` and remove spaces.

```text
Operator$Signup$Approved
=> OPERATOR.SIGNUP.APPROVED
```

When a module name is supplied and is not already the first segment, it is
prepended.

### 7.2 API

- `listen({ eventName, multiple? }, handler?, moduleName?)`
- `emit({ eventName, payload }): Promise<boolean>`
- `registerEmitter(eventName, moduleName?)`
- `setAdapter(adapter)`
- `getAllRegisteredEvents()`
- `getAllRegisteredEventsIntoCluster()`
- `close()`
- compatibility: `listenEvent`, `emitEvent`

Example:

```ts
events.registerEmitter('OPERATORS.OPERATOR.CREATED', 'OPERATORS')

events.listen(
	{ eventName: 'OPERATORS.OPERATOR.CREATED' },
	async event => {
		console.info(event.payload)
	},
	'NOTIFICATIONS',
)

const targeted = await events.emit({
	eventName: 'OPERATORS.OPERATOR.CREATED',
	payload: { uuid: Bun.randomUUIDv7() },
})
```

`emit()` returns `false` when the event/emitter is not registered or when no
listener target exists. A `true` result means targets were selected and adapter
publish calls completed according to that adapter; it is not an end-to-end
consumer acknowledgement.

### 7.3 Single and multiple delivery

- `multiple: false` selects the first registered listener instance globally.
- `multiple: true` selects one listener instance per registered cluster and
  advances that cluster's round-robin cursor.
- On a selected local instance, all registered local handlers run for a
  multiple event; only the first local handler runs for a single event.

Once any listener registers an event with `multiple: true`, the registry entry
remains multiple for that process.

### 7.4 Registry liveness

Every five seconds, each instance re-announces local listeners and emitters.
Remote listener instances silent for more than fifteen seconds are evicted.
When the first listener disappears, a replacement is selected. The local
instance is not evicted by its own registry.

Call `close()` during shutdown to stop the heartbeat, announce instance removal,
and close the active adapter.

### 7.5 Adapters

`RedisEventsAdapter` is the default and uses `RedisClient` pub/sub.

```ts
events.setAdapter(new RedisEventsAdapter(redis))
```

`SQSEventsAdapter` accepts:

- `queueUrl` (required)
- `region` or an injected `SQSClient`
- `pollIntervalMs`
- `waitTimeSeconds`
- `visibilityTimeoutSeconds`
- `maxMessages`
- FIFO `messageGroupId`
- `messageDeduplicationId(payload)`

SQS queue topology, IAM, dead-letter policy, and FIFO requirements remain the
consumer's responsibility.

## 8. Persistence and Shared State

### 8.1 `Dependencies`

Process-local static dependency container:

```ts
Dependencies.add('db', db)
const resolved = Dependencies.get<MongoClient>('db')
Dependencies.has('db')
Dependencies.remove('db')
Dependencies.clear()
```

Duplicate keys throw. Missing keys return `null`. There are no scopes or
automatic lifecycle hooks.

### 8.2 MongoDB

```ts
const db = MongoClient.getInstance({
	connectionString: process.env.MONGO_URI!,
	database: process.env.MONGO_DB!,
})
await db.connect()
```

API:

- `connect()`
- `close()`
- `getDB()`
- `getCollection<T>(name)`
- `ObjectId(id)`
- `MongoClient.paginate(collection, query?, fields?, options?)`

The singleton's first connection configuration wins. `getDB()` throws until
`connect()` succeeds. `ObjectId(id)` validates before construction.

Pagination defaults:

- `page: 1`
- `limit: 30`
- `sort: { added: -1 }`

`page` and `limit` must be greater than zero. The result is:

```ts
{
  docs: T[]
  count: number
  limit: number
  page: number
  totalPages: number
}
```

`MongoDBStorage` is an internal base class and has no supported package import.
Repository code using it must resolve a `MongoClient` under the `Dependencies`
key `db`.

### 8.3 Redis/Valkey

```ts
const redis = RedisClient.getInstance(process.env.REDIS_URL)
await redis.connect()
```

Connection URI resolution on the first singleton call:

1. explicit URI;
2. `REDIS_URL`;
3. `VALKEY_URL`;
4. Bun client defaults.

A host without a URI scheme is normalized to `redis://host:6379` unless it
already includes a port.

API:

- `connect`, `close`, `isConnected`
- `hset`, `hget`, `hgetall`
- `setCache`, `getCache`
- `counter`
- `subscribe`, `unsubscribe`, `publish`

Pub/sub uses dedicated duplicated connections. `publish()` and `subscribe()`
return `void`; connection and delivery errors are logged asynchronously rather
than returned to the caller. Payloads are JSON serialized.

### 8.4 Multi-engine `SQL`

```ts
const sql = new SQL({
	type: 'postgres', // 'mysql' | 'sqlite'
	url: process.env.DATABASE_URL,
	tls: { rejectUnauthorized: true },
})
```

For SQLite, `url` is a filename and defaults to `db.sqlite`. For PostgreSQL or
MySQL, omitting `url` delegates connection defaults to `Bun.SQL`.

Schema API:

- `createTable`
- `addTableColumns`
- `createIndex`
- `dropTable`
- `getAllTables`
- `getTableSchema`
- `validateTableSchema`

Data API:

- `insert`
- `select`
- `selectPaginate`
- `update`
- `updateById`
- `delete`
- `deleteById`
- `count`

`translateMongoJsonToSql` supports `$eq`, `$ne`, `$gt`, `$gte`, `$lt`, `$lte`,
`$in`, `$nin`, and `$like`.

Identifier safety:

- table, column, filter, and sort identifiers are allow-listed;
- dot-separated qualified identifiers are accepted;
- `*` is accepted as a projection;
- raw expressions and aliases such as `COUNT(*) AS total` are rejected;
- filter and write values are bound as parameters.

Write results:

- `insert` returns `{ lastInsertRowId?, changes, affectedRows }`;
- `update` and `delete` return an affected-row count.

Known constraint: the PostgreSQL/MySQL bridge currently converts `?`
placeholders by splitting the completed query string. A literal `?` inside SQL
text can desynchronize bindings. Keep SQL generated through the provided
helpers and do not embed question marks in schema/type fragments used by a
query.

Validate and bound pagination values before passing request input. `limit` and
`page` are numeric TypeScript inputs but are rendered into the generated SQL.

### 8.5 Direct `SQLite`

```ts
const memory = new SQLite({ type: 'memory' })
const file = new SQLite({ type: 'file', filename: './service.sqlite' })
```

API:

- `createTable`, `addTableColumns`, `createIndex`, `dropTable`
- `insert`, `select`, `update`, `delete`
- `getAllTables`, `getTableSchema`
- `close`

This class automatically adds an `added` integer column in `createTable()` and
an `added` timestamp value in `insert()`. Both methods mutate the object passed
by the caller. The direct wrapper does not provide the `SQL` class's pagination
or count methods.

Identifiers use the same validation as `SQL`; values are bound parameters.

## 9. Runtime Utilities

### 9.1 `Cluster`

```ts
const cluster = new Cluster({
	name: 'api',
	maxCPU: 4,
	watchMode: false,
	args: [],
})

cluster.start('./modules/server.ts', error => {
	console.error(error)
})
```

The cluster:

- limits workers to available hardware concurrency;
- spawns the current Bun executable;
- can add Bun arguments and `--watch`;
- broadcasts startup/name commands over IPC;
- forwards worker broadcasts using the `>>.<<|` prefix;
- kills workers when the parent receives `SIGINT` or `SIGTERM`.

Public API:

- `start`
- `onWorkerMessage`
- `sendMessageToWorkers`
- `getCurrentFile`
- `getCurrentWorkers`

There is currently no public stop method, worker restart policy, readiness
coordination, or rolling-restart mechanism. Worker servers must use
`clustering: true` to enable Bun `reusePort`.

### 9.2 `SSE`

`SSE` builds a `text/event-stream` response from a raw Web `Request`.

```ts
import { SSE } from 's42-core'

Bun.serve({
	port: 3000,
	routes: {
		'/stream': (request: Request) => {
			const stream = new SSE(request)
			const timer = setInterval(() => {
				stream.send({
					eventName: 'tick',
					eventPayload: { now: Date.now() },
				})
			}, 1_000)

			request.signal.addEventListener('abort', () => {
				clearInterval(timer)
				stream.close()
			})

			return stream.getResponse()
		},
	},
})
```

API:

- `getResponse`
- `getUUID`
- `send`
- `close`

The stream flushes once per second. Messages sent before Bun supplies the direct
stream controller can be dropped.

Important integration constraint: `RouteControllers` passes a normalized request
that does not currently preserve `Request.signal`. Use `SSE` only where the raw
request is available, and always release timers/resources on abort.

### 9.3 `CoreStats`

Automatic mode:

```bash
ENABLE_CORE_STATS=true
```

When the environment value is `true` or `1` before `RouteControllers` is
constructed, it injects `GET /core/stats` unless that exact GET route already
exists.

The payload contains:

- controller and endpoint counts;
- loaded module counts and manifests;
- `free -m`, `df -h`, `uptime`, `who`, and
  `cpupower frequency-info` output.

Missing host commands do not fail the endpoint; their sections report
`ok: false` and raw error text.

Security: the route adds no authentication or authorization and exposes host
details, connected-user output, route inventory, and module metadata. Keep it
disabled on public services unless access is protected by a trusted layer.

Manual API:

```ts
const stats = new CoreStats({
	enabled: true,
	path: '/internal/core/stats',
	commandRunner,
})
```

- `isEnabled`
- `getPath`
- `getController`
- `getStats`

A custom path applies to that manually created instance. Automatic injection
uses the default `/core/stats` singleton and environment flag.

### 9.4 Logger

Levels:

```text
debug < info < warn < error < silent
```

The default is `debug`. Initial level resolution uses `S42_LOG_LEVEL`, then
`LOG_LEVEL`.

```ts
import { logger, setLogLevel, setLogSink } from 's42-core'

setLogLevel('warn')
logger.warn('degraded')

setLogSink({
	debug: (...args) => transport.debug(args),
	info: (...args) => transport.info(args),
	warn: (...args) => transport.warn(args),
	error: (...args) => transport.error(args),
})
```

### 9.5 Test namespace

```ts
import { Test } from 's42-core'

Test.Init('Starting smoke test')
Test.Request('GET', '/health')
Test.Ok('Health endpoint responded')
Test.Finish()
```

These are console-formatting helpers, not a replacement for `bun:test`.

### 9.6 Internal Mailgun and template helpers

`src/Mailgun` and `src/ViewTemplates` are documented for repository maintainers
only. They do not have supported package imports.

`ViewTemplates` does not HTML-escape interpolated values. Never render
untrusted content without an approved escaping strategy.

## 10. Production Review Checklist

- Provide a sanitized `Server.error` handler.
- Enforce an explicit CORS policy outside the current fixed router headers.
- Trust forwarded IP headers only behind a controlled proxy.
- Keep `CoreStats` disabled or authenticated and network-restricted.
- Validate pagination limits and avoid unbounded database reads.
- Register event emitters before emitting and call `EventsDomain.close()` on
  shutdown.
- Treat singleton configuration as immutable after first initialization.
- Close MongoDB, Redis, SQLite, event, and worker resources explicitly.
- Use the logger sink for protected structured diagnostics.
- Test PostgreSQL, MySQL, SQS, and external-service behavior against the actual
  deployment environment; unit tests do not prove provider connectivity.

## 11. Known Current Behaviors

- Global hooks auto-advance and cannot return a replacement response.
- After hooks cannot alter the controller response.
- `RouteControllers` CORS headers are fixed and permissive.
- The default server error page exposes stack details.
- Module `dependencies` is metadata only.
- Controller-level `enabled` is not enforced by the loader.
- Models/services/types are not auto-discovered.
- `getHooks()` is not populated by controller-level `mws` modules.
- `modules/operators/controllers/operatorList.ts` imports a missing
  `../events/emit` fixture, so `bun run typecheck:modules` and the local module
  demo do not currently complete.
- MongoDB, Redis, and EventsDomain are first-configuration-wins singletons.
- SQL PostgreSQL/MySQL placeholder translation cannot safely represent a literal
  `?` in generated SQL.
- `SSE` requires a raw request, while normal controller handlers receive a
  normalized object.
- `Cluster` has no public stop/restart/readiness API.
- Mailgun, ViewTemplates, and MongoDBStorage are internal.
